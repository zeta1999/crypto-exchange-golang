# Benchmarks

## pkg/decimal A/B — exact core vs float64 back-end

The decimal package ships two numerical cores (PLAN §9.7):

- **Exact (default build):** 128-bit fixed-point (2^64 scale at 10^-18), allocation-free
  `math/bits` limbs; `Mul` is 128×128→256 limb math, `Div` is 256÷128 binary long division.
  Always overflow-safe and bit-deterministic.
- **Float (`-tags decimal_float64`):** raw float64 behind the same API (type alias).
  Deliberately fast/loose; for A/B measurement, not as a production default.

Re-run the numbers (benchtime 10,000,000 ops; pass a second arg to override, e.g.
`make bench-decimals BENCHTIME=200000000x`):

```
make bench-decimals        # or: scripts/bench-decimals.sh
```

Both cores are allocation-free (`0 B/op`), so the comparison below is pure ns/op.
`float Add+Div` is one line per op (Add then Div back-to-back), hence its low number
is not directly comparable to a single exact op; it shows the *floor* of the loose
path (a float64 ALU op).
